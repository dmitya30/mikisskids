# Архитектура MIKISSKIDS

**Статус:** проектное решение для MVP  
**Дата:** 23.07.2026

## Принцип

Первый прототип создаётся без фреймворка и сборщика:

- семантический HTML;
- общий CSS;
- небольшой JavaScript;
- локальные SVG, изображения и видео;
- отсутствие внешних шрифтов и скриптов без необходимости.

Это сокращает стоимость, ускоряет загрузку и упрощает размещение на VPS.

## Маршруты

```text
/                       Главная
/chair/                 Стульчик-трансформер
/travel-seat/           Чемодан-кресло
/about/                 О бренде
/delivery/              Доставка и оплата
/legal/agreement/       Пользовательское соглашение
/legal/offer/           Публичная оферта
/legal/privacy/         Политика обработки персональных данных
/legal/consent/         Согласие на обработку персональных данных
```

Старые адреса текущего сайта после переноса должны получить редиректы:

```text
/agreement       → /legal/agreement/
/public_offer    → /legal/offer/
/personal_data   → /legal/privacy/
```

## Дизайн-система

### Палитра

```text
Основной фон:       #F4F1EB
Дополнительный фон: #E9E4DC
Основной текст:     #171715
Вторичный текст:    #68645E
Тёплый акцент:      #8A7258
Белый:              #FFFFFF
Линии:              rgba(23, 23, 21, 0.14)
```

Палитра может уточняться после сборки первого экрана.

### Типографика

- выразительный, но читаемый заголовочный шрифт;
- нейтральный гротеск для основного текста и интерфейса;
- локальное хранение лицензированных файлов;
- основной текст на мобильном устройстве - не менее 16 px;
- декоративное начертание не применяется к длинным текстам.

До выбора лицензированных шрифтов используются системные резервные наборы.

## Медиа

### Изображения

- оригиналы не изменяются;
- рабочие версии позднее конвертируются в WebP и/или AVIF;
- для каждого изображения задаются `width`, `height` и `alt`;
- ниже первого экрана используется `loading="lazy"`;
- изображения не должны искажать конструкцию товара.

### Видео

Чемодан:

```text
assets/video/travel-seat-transform.mp4
```

Стульчик:

```text
assets/video/chair-brown.mp4
```

Правила:

- без автоматического звука;
- чемодан: `preload="metadata"` или `preload="none"`;
- стульчик: управляемое воспроизведение;
- для каждого видео требуется обложка;
- видео не должно блокировать отрисовку страницы.

## Социальные ссылки

Иконки:

```text
assets/icons/social/telegram.svg
assets/icons/social/max.svg
```

Будущая конфигурация:

```text
telegramPersonal
telegramChannel
maxPersonal
maxChannel
```

Пока URL не получены, ссылки не выводятся посетителю.

## Форма заказа

Статический прототип содержит интерфейс формы без реального списания.

Планируемые поля:

- имя;
- телефон;
- email;
- город;
- способ доставки;
- комментарий;
- согласие с офертой;
- отдельное согласие на обработку персональных данных.

Рекламная рассылка, если появится, должна иметь отдельное необязательное
согласие.

## Серверный этап

Backend должен:

1. принять заказ;
2. проверить поля;
3. получить актуальную цену товара на сервере;
4. создать номер заказа;
5. сохранить заказ;
6. инициировать платёж в Т-Банке;
7. вернуть ссылку на платёжную форму;
8. проверить уведомление Т-Банка;
9. обновить статус заказа;
10. уведомить продавца.

## Данные

Для MVP планируется SQLite.

Основные сущности:

```text
products
orders
order_items
payments
```

Цена и итоговая сумма не принимаются от браузера как доверенные данные.

## Безопасность

- секреты Т-Банка только в `.env` на VPS;
- `.env` исключается из Git;
- HTTPS обязателен для коммерческого контура;
- входящие платёжные уведомления проверяются на сервере;
- персональные данные не записываются в клиентские логи;
- staging закрывается Basic Auth;
- резервные копии базы создаются вне публичной директории;
- административная панель в MVP не создаётся.
