## Аналитика

Счётчик Яндекс Метрики `111056887` установлен:

- на основном сайте `mikisskids.ru`;
- на платёжном поддомене `pay.mikisskids.ru`;
- только через единый consent-модуль;
- без Вебвизора;
- с сохранением выбора в cookie `mk_cookie_consent`
  для домена `.mikisskids.ru`.

Проверены сценарии:

- до согласия код Метрики не загружается;
- отказ сохраняется и не блокирует оформление заказа;
- выбор действует при переходах между основным доменом и `pay`;
- после согласия загружается только счётчик `111056887`;
- пользователь может изменить решение через «Настройки cookies».

С Tilda удалены ранее установленные legacy-счётчики:

- Яндекс Метрика `107009480`;
- Top.Mail.Ru / VK Pixel `3752851`.

Для двух возможных страниц возврата после оплаты созданы раздельные
диагностические URL-цели:

- `/success_payment`;
- `/payment-success`.

Открытие success-страницы не считается самостоятельным подтверждением
оплаты. Контрольный платёж подтвердил фактический Return URL
`https://pay.mikisskids.ru/payment-success`; финансовый статус
подтверждается через Т-Бизнес, Tilda и серверный webhook.

Ручные цели Метрики и рекламная воронка настроены. Проверены
события начала оформления, открытие checkout, отправка формы, клики
по контактам и две диагностические success-цели. Проверка выполнена
одним тестовым визитом через `_ym_debug=2`; техническая цепочка целей
работает. Success-страницы остаются диагностическими и не заменяют
серверное подтверждение оплаты.

## Проверка платёжного цикла 29.07.2026

Фактически проверены:

- реальная оплата через Tilda и Т-Банк;
- успешное завершение оплаты;
- Return URL `https://pay.mikisskids.ru/payment-success`;
- отображение оплаченной заявки в Tilda;
- полный возврат контрольной оплаты 10 ₽;
- отправка оплаченной заявки из Tilda в webhook;
- сохранение заказа в SQLite;
- восемь unit-тестов webhook;
- production deploy коммита `83d337f`.

Первоначально оплаченный webhook возвращал HTTP 400. Безопасное
диагностическое логирование подтвердило причину: production payload
Tilda не содержал `tranid`.

Реализован следующий приоритет стабильного идентификатора:

1. `tranid`;
2. хеш идентификатора заказа Tilda;
3. хеш `paymentid`.

Payload без стабильного идентификатора по-прежнему отклоняется.
После исправления новая оплаченная заявка успешно сохранена в SQLite
со статусом `paid_reported_by_tilda`, а Tilda показала успешную отправку
в Webhook.

Временные платёжные суммы 10 ₽ и 1 ₽ удалены. Платёжная сумма снова
составляет 50 000 ₽. Проверка двух возвратов по 1 ₽ и соответствующих
чеков передана владельцу, имеющему доступ к Т-Бизнесу.

Источник суммы в текущем MVP - товарная ссылка Tilda. Backend не создаёт
платёж и не сверяет сумму с серверным каталогом. Кабинет Т-Бизнеса и
онлайн-касса остаются источниками истины по оплате, возврату и чекам.
